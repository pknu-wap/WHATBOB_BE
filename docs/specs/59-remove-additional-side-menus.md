# #59 추가 반찬과 단독 양념·소스 메뉴 정리

운영 메뉴에서 장류·양념류와 합의한 반찬·사이드·국 106개를 제거한다. [Fix DB 이슈 #59](https://github.com/pknu-wap/WHATBOB_BE/issues/59)

## 삭제 범위

| 기준 | 운영 DB 사전 조회 |
| --- | ---: |
| 대분류가 `장류, 양념류`인 메뉴 | 10 |
| 기본 이름이 감자볶음, 김치볶음, 달걀말이, 어묵볶음, 도라지생채인 메뉴 | 33 |
| 기본 이름이 감자튀김, 치즈볼, 치즈스틱, 팝콘, 견과, 과일인 메뉴 | 43 |
| 기본 이름이 미역국, 콩나물국인 메뉴 | 20 |

- 기본 이름은 원본 식품명에서 첫 밑줄 앞의 이름이다. 예를 들어 `과일_하루 한 컵 RED`는 포함한다. 과일샐러드, 제육볶음, 양념치킨, 감자탕 같은 메뉴는 유지한다.
- 원본에는 같은 기준에 해당하는 식품코드가 213개 있다. 213개를 기존 삭제 목록에 추가하고, 정제 CSV와 공유 CSV·JSON에서는 이에 해당하는 106개를 제거한다. 이전 원본 CSV를 사용해도 동일한 코드를 다시 적재할 수 없다.
- 기존 DB 정리 스크립트를 그대로 실행한다. 삭제 대상과 연결된 추천 피드백·스냅샷을 정리하고 영향이 있는 질문 점수를 다시 계산한다. 운영 사전 조회에서 추천 피드백 11건, 피드백 상태 8건, 스냅샷 4건, 수정할 과거 추천 25건을 확인했다. 적용 직전에 다시 조회한다. [기존 DB 정리 명세](35-remove-side-dishes-and-desserts.md)

## 운영 반영

1. 이슈에 연결한 브랜치의 PR에 리뷰 승인을 받고 `main`에 병합한다.
2. 운영 서버에서 승인된 커밋을 반영하고 DB 백업과 삭제 대상 사전 조회를 확인한다.
3. 백엔드 쓰기를 잠시 멈추고 `python -m scripts.remove_side_dishes_and_desserts --apply`로 정리한다.
4. 사전 조회 명령에서 삭제 대상이 0개인지 확인하고 백엔드를 시작한다. 공개 API 응답과 남은 메뉴 수를 확인한다.
