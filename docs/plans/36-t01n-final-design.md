# #36 T01N 최종 설계 확인안

- 상태: 2026-11-17 사용자 확인 완료 (`D01`~`D12` 전체 확정).
- 범위: 방 상태 버전(`state_version`) 관리, DB 기반 알림 발송 대기(`Transactional Outbox`), 소켓 전송 실패 시 제한된 재시도(1·3·5·10·30초, 최초 실패 기준 최대 60초), 완료/종료 시 원문 정리 및 3일 요약 보관.
- 상세 근거: [T01N 아키텍처 질의응답 기록](36-t01n-notification-architecture.md), [T01N 티켓](36-tickets/T01N-durable-room-notifications-and-versions.md).

## 1. 확정된 핵심 아키텍처 결정 요약 (`D01` ~ `D12`)

| 결정 ID | 주제 | 사용자 확정 선택 | 핵심 설계 계약 |
| :--- | :--- | :--- | :--- |
| **D01~D03** | 상태 버전·Outbox 저장 원자성 | **1번 확정** | 방 업무 변경 트랜잭션 안에서 `rooms.state_version` 증가와 발송 대기 레코드(전체 공통 snapshot 포함)를 함께 commit한다. 업무 rollback 시 알림도 함께 취소된다. |
| **D04** | 발송 실행 조정 위치 | **1번 확정** | 단일 API 프로세스 내 발송 기록별 메모리 잠금을 공유하여 동일 알림의 중복 동시 실행을 막고, DB 상태는 영속 보존해 서버 재시작 후 복구한다. |
| **D05** | 60초 전체 기한과 진행 중 전송 취소 | **1번 확정** | 최초 실패 관찰 시각부터 60초 고정 기한이 도달하면 진행 중인 미완료 소켓 전송 기다림도 즉시 중단하고 기한 만료로 종료한다. |
| **D06** | 재시작 시 결과 불명 최초 전송 처리 | **2번 확정** | 최초 전송 시작 표시만 있고 결과·실패 기한이 DB에 없는 기록은 서버 재시작 시 재전송하지 않고 결과 불명(`UNKNOWN_AFTER_START`)으로 안전 종료한다. |
| **D07** | 종료 후 원문 정리와 요약 보관 | **2번·3일 확정** | 발송 종료(성공·수신자 없음·기한 만료·방 종료·결과 불명) 시 큰 snapshot 원문(`payload_json`)은 제거(`NULL`)하고, 처리 요약 메타데이터만 종료 시각부터 3일간 보관한다. |
| **D08** | 방 삭제 시 요약 이력 연결 방식 | **1번 확정** | 실제 방 연결은 nullable FK + `ON DELETE SET NULL`을 사용하고, 요약 조사를 위한 방 식별자·코드는 별도 이력 컬럼으로 보존한다(3일 보관 기한 유지). |
| **D09** | 만료된 3일 요약 정리 주기 | **2번 확정** | 실행 완료 후 1시간 간격 백그라운드 작업으로 한 번에 100건씩 최대 10묶음(최대 1,000건) 삭제하며 묶음별 독립 트랜잭션으로 실패를 격리한다. |
| **D10** | 변경 성공 HTTP 응답의 전체 공통 상태 | **1번 확정** | 적용 가능한 변경 요청의 성공 응답에 최종 저장 버전의 전체 공통 상태를 함께 반환한다. 전체 상태를 적용했을 때만 버전을 올리고 응답·알림 역순으로 화면이 되돌아가지 않게 한다. |

| **D12** | 소켓 전송 후 DB 결과 저장 실패 복구 | **1번 확정** | 살아 있는 프로세스가 관찰한 실제 전송 결과와 최초 실패 시각(60초 고정 기한)을 메모리에 보존한 채 DB 결과 저장부터 복구하며, 저장 복구 전 무분별한 재전송을 보류한다. |

## 2. 확정된 처리 흐름

1. **업무 트랜잭션 내 Outbox 기록**:
   - 방 입장, 퇴장(`T01` 공통 정리 이후), 접속 상태 변경, 방 시작/제출/투표 등 방 상태가 변할 때 같은 DB 트랜잭션 안에서 `rooms.state_version`을 1 증가시키고, 해당 버전의 공통 방 상태 스냅샷을 알림 테이블에 `PENDING`으로 저장한다.
2. **DB 잠금 해제 후 비동기/직후 발송**:
   - 상위 트랜잭션 commit이 성공한 뒤에만 발송기를 호출한다. 소켓 전송 중에는 방 DB 행 잠금을 잡고 있지 않는다.
3. **재시도 및 종료 규칙**:
   - 연결별 전송 제한은 2초를 유지한다.
   - 1명이라도 소켓 전송에 실패하면 최초 실패 시각(`first_failed_at`)과 마감 시각(`deadline_at = first_failed_at + 60s`)을 고정하고 `1s → 3s → 5s → 10s → 30s` 간격으로 현재 유효한 방 연결 전체에 동일 버전 스냅샷을 재전송한다.
   - 현재 유효한 연결이 0명이면 수신자 없음으로 즉시 종료하고, 방이 닫히면(`room.closed`) 일반 대기 알림을 즉시 종료 처리한다.
4. **프론트엔드 버전 비교 계약**:
   - 모든 REST 방 조회 응답과 WebSocket 방 상태 이벤트는 동일한 `state_version`을 포함한다. 클라이언트는 이미 적용한 버전보다 작거나 같은 이벤트는 무시한다.
