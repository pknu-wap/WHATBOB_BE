# T05: 주문서 작성 중 퇴장과 방장 계속·취소 선택

## Parent

[개발 명세 #43](https://github.com/pknu-wap/WHATBOB_BE/issues/43), 원본 요청 #36.

## What to build

주문서 작성 중 일반 참여자의 퇴장이 확정되면 작성·제출 상태를 보존한 채 멈추고, 방장이 퇴장자를 제외하고 계속 진행하거나 라운드를 취소할 수 있게 한다. 남은 인원이 두 명 미만이면 대기실로 복귀한다.

## Acceptance criteria

- [ ] 명시적 퇴장 및 기존 60초 유예가 만료된 모든 정리 경로에서 같은 라운드 일시 정지 규칙이 적용된다.
- [ ] 단순 연결 단절에는 먼저 기존 유예를 적용하고, 유예 내 재접속은 제출 상태를 유지한다.
- [ ] 방장에게 실제 퇴장자와 예/아니요 선택을, 다른 참여자에게 결정 대기 상태를 제공한다.
- [ ] 결정 대기 중 추가 주문서·투표 제출과 자동 단계 전환이 막히고 기존 작성·제출 상태는 보존된다.
- [ ] 방장만 현재 퇴장 목록에 대해 결정한다. 연속 퇴장·중복 결정·오래된 결정이 누락된 참여자나 중복 진행을 만들지 않는다.
- [ ] 예를 선택하면 남은 참여자의 제출 답변을 유지하고 남은 인원 기준으로 작성·후보 확정을 이어간다. 기존 공통 제외 조건 스냅샷은 유지한다.
- [ ] 아니요를 선택하면 라운드를 취소하고 남은 참여자와 대기실로 돌아간다. 퇴장자를 복귀시키지 않는다.
- [ ] 두 명 미만이면 계속 선택 없이 이유를 안내하고 취소한다. 방장 퇴장·유예 만료·방 만료는 기존 종료 정책을 따른다.
- [ ] 진행 상태·결정 버전·취소 사유의 저장과 마이그레이션, REST·WebSocket 상태 복구·권한·프론트 확인창 계약을 함께 제공한다.
- [ ] 실제 요청과 유예·정리 실행 경계로 계속/취소·최소 인원·동시 퇴장을 검증한다.
