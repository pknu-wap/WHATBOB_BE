# T02: 방장 시작부터 개인 주문서 질문 조회까지

## Parent

[개발 명세 #43](https://github.com/pknu-wap/WHATBOB_BE/issues/43), 원본 요청 #36.

## What to build

방장이 두 명 이상을 모아 라운드를 시작하면 이번 참여자와 공통 제외 조건이 고정되고, 각 참여자가 기존 개인 질문 로직으로 주문서 질문을 받을 수 있게 한다. 새로고침 후에도 같은 진행 상태를 조회할 수 있어야 한다.

## Acceptance criteria

- [ ] 인증된 방장만 대기실에서 시작하며 두 명 미만이면 시작하지 않는다.
- [ ] 시작과 동시 참여 요청이 경합해도 참여 인원과 공통 제외 조건이 일관되게 고정된다.
- [ ] 시작 시 참여자 전원의 저장된 알레르기·섭취 불가·비선호 조건을 라운드에 보존한다. 이후 개인 설정 변경으로 이번 조건이 바뀌지 않는다.
- [ ] 공통 제외 후 메뉴가 없으면 이유를 안내하고 대기실을 유지하거나 취소된 라운드로 대기실에 복귀한다. 제외 조건을 풀지 않는다.
- [ ] 시작 후 신규 참여는 거절하고 기존 참여자의 유예 내 재접속과 상태 조회는 허용한다.
- [ ] 참여자는 개인 질문 선택 이력을 반영한 기존 질문을 받는다. 다른 사람의 답변·제외 설정은 공개하지 않는다.
- [ ] 라운드와 본인 진행 상태를 인증된 REST로 조회하고 WebSocket 상태 변경 알림을 받을 수 있다.
- [ ] 필요한 저장 구조와 기존 데이터 보존을 위한 명시적 마이그레이션을 함께 제공한다. 기존 방 상태·생성·참여 계약의 변경점을 문서화한다.
- [ ] REST·WebSocket 검증으로 시작 권한·최소 인원·조건 고정·질문 조회·신규 참여 차단을 확인한다.
- [ ] Q19·Q20의 지원 여부를 확정하는 인터페이스를 추가하지 않는다.

## Blocked by
