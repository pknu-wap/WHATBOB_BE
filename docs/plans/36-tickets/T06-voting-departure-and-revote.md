# T06: 투표 중 퇴장 후 후보 정리와 전원 재투표

## Parent

[개발 명세 #43](https://github.com/pknu-wap/WHATBOB_BE/issues/43), 원본 요청 #36.

## What to build

투표 중 일반 참여자가 퇴장한 뒤 방장이 계속 진행하면 남은 사람의 주문서는 유지하고, 퇴장자의 후보 기여를 정리해 새 회차에서 전원이 다시 투표할 수 있게 한다.

## Acceptance criteria

- [ ] 투표 중 실제 퇴장에도 방장 결정 대기·제출 차단·최소 두 명·아니요 취소 정책을 적용한다.
- [ ] 예를 선택하면 퇴장자만 제안한 후보를 제거하고, 남은 사람도 제안한 같은 메뉴는 유지한다.
- [ ] 남은 참여자의 제출 주문서와 공통 제외 조건은 유지하며 개인 후보를 다시 추첨해 바꾸지 않는다.
- [ ] 이전 회차의 표를 새 회차 집계에서 제외하고 남은 사람 전원의 투표 완료 상태와 화면 선택을 초기화한다.
- [ ] 이전 회차의 재전송·지연 제출은 새 회차의 표가 될 수 없다. 새 회차도 제출 후 수정 불가 규칙을 따른다.
- [ ] 후보가 하나만 남으면 무투표 결과로 진행하고, 두 명 미만이면 라운드를 취소한다.
- [ ] 결정 대기 중 추가 퇴장과 마지막 투표 제출이 경합해도 유효한 한 상태로 수렴하고 중간 득표·개인별 표를 노출하지 않는다.
- [ ] 변경된 후보·투표 회차·진행 상태를 REST 재조회와 WebSocket 알림으로 복구할 수 있다.
- [ ] 필요한 저장·마이그레이션과 프론트 초기화 계약을 함께 제공하고, 실제 요청으로 후보 기여자·표 초기화·지연 요청 거절을 검증한다.
