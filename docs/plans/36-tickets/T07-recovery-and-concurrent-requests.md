# T07: 연결 유실·서버 재시작·동시 요청에서도 진행 복구

## Parent

[개발 명세 #43](https://github.com/pknu-wap/WHATBOB_BE/issues/43), 원본 요청 #36.

## What to build

연결이 끊기거나 서버가 재시작되고 요청이 중복·경합해도 참여자가 DB에 보존된 라운드·제출·투표·방장 결정 대기·결과 상태로 복귀할 수 있게 전체 흐름을 완성한다. 이미 제공된 명령이 실제 운영 DB의 잠금·참조·정리 동작에서도 일관되게 유지되도록 보완한다.

## Acceptance criteria

- [ ] 상태 변경 알림을 놓치거나 연결이 다시 생겨도 인증된 상태 조회로 같은 진행 화면을 복원한다.
- [ ] 서버 재시작 복구에서 기존 유예가 연장되지 않고 작성·제출·투표 회차·방장 결정 대기가 DB 기준으로 복원된다.
- [ ] 시작과 참여, 마지막 주문서·투표와 퇴장, 방장 결정과 연속 퇴장, 유예 만료와 재접속 경합에서 유효한 한 결과가 나온다.
- [ ] 기존 단일 API 프로세스 조건과 인증·계정 전환 제한을 유지하고 추가 메시지 시스템을 요구하지 않는다.
- [ ] 방장 종료·방 만료·방 삭제 시 새 라운드 관련 참조를 남기거나 기존 개인 기록을 잘못 삭제하지 않는다.
- [ ] 각 선행 티켓의 증분 마이그레이션을 기존 방·참여·개인 기록이 있는 격리 DB에서 적용·재실행·중단 후 재개해 데이터 보존을 확인한다.
- [ ] 실제 MySQL 독립 세션 경합과 마이그레이션 검증을 실행한다. 환경이 없으면 해당 항목을 미검증으로 명시하고 기능 테스트 통과와 구분한다.
- [ ] 기존 방·개인 추천·사용자 설정·인증·재접속 회귀와 REST·WebSocket 전체 흐름 검증을 수행하고 프론트 복구·재전송 계약을 최종 문서화한다.
- [ ] 아직 보류인 Q19·Q20을 이 통합 작업에서 임의로 결정하거나 전체 기능 완료로 숨기지 않는다.

## Blocked by
