# T01N: 방 알림 저장·재시도와 상태 버전 관리

## Parent

[개발 명세 #43](https://github.com/pknu-wap/WHATBOB_BE/issues/43), 원본 요청 #36. 2026-11-16 사용자 아키텍처 질의응답 D07~D13에서 추가·분리한 작업이다.

## What to build

기존 방의 상태 변경과 알림을 일관된 증가 버전으로 연결하고, 퇴장 알림을 DB에 함께 저장해 일시적 전송 실패·서버 재시작 이후에도 제한 시간 안에서 재시도한다. 단, 최초 전송 시작은 확인되지만 결과가 불명확한 기록은 재전송 없이 결과 불명 종료한다. 프론트는 알림에 포함된 상태를 버전으로 비교해 중복·오래된 정보를 무시하고 최초 입장·재접속에는 최신 방 조회로 복구한다.

DB 스키마·명시적 마이그레이션·기존 방 명령과 조회·실제 WebSocket 전송 결과·발송 대기 실행·프론트 계약·회귀 검증을 함께 완성하는 세로 티켓이다. 이후 주문서·투표 기능은 이 상태·알림 계약을 확장해 사용한다.

## Acceptance criteria

- [ ] 퇴장 변경·상태 버전 증가·해당 버전의 발송 대기가 같은 트랜잭션에서 저장·취소된다. 계정 전환 등 상위 트랜잭션을 중간 확정하지 않는다.
- [ ] 모든 기존 일반 참여자 정리 경로를 다루고 최종 커밋 이후 상위 호출 경계가 발송을 명시적으로 호출한다. 새 라운드의 방장 결정 정책은 후속 티켓에서 연결한다.
- [ ] 단일 API 프로세스에서 최초 전송과 재시도는 공통 발송 진입점과 발송 기록 ID별 메모리 잠금을 사용한다. 잠금 획득 후 DB의 완료 여부·다음 시각·기한을 다시 확인하며 같은 기록의 동시 실행을 막는다. 다른 기록·여러 방을 전역 잠금으로 직렬화하지 않고 잠금 수명도 관리한다. 발송 대기·결과·기한은 DB에 보존하며 DB 처리 권한 임대는 추가하지 않는다.
- [ ] 서버 소켓 전송 결과로 완료·실패를 구분하며 프론트 ACK는 추가하지 않는다. 일부 연결 실패 시 해당 방 알림 전체를 현재 유효한 연결에 재전송한다.
- [ ] 최초 전송과 각 재시도 직전에 현재 방 참여 자격을 DB에서 방 단위로 일괄 확인하고 해당 자격이 있는 연결만 대상으로 삼는다. 기존 토큰 만료·퇴장 연결 정리도 유지하며 DB 확인 실패를 수신자 없음으로 종료하지 않는다. 소켓 전송 중 DB 잠금을 유지하지 않는다.
- [ ] 각 실패 후 다음 시도 전 대기 간격은 1초 → 3초 → 5초 → 10초 → 30초다. 전체 기한은 최초 전송 실패부터 60초이며 기한이 지난 새 전송을 시작하지 않는다. 재실패·재시작으로 기한을 연장하지 않는다.
- [ ] 전체 60초 기한에 진행 중인 미완료 전송의 기다림도 중단한다. 기한이 있는 전송은 기존 연결별 2초와 전체 남은 시간 중 짧은 범위를 적용하고 기한에 취소를 요청한다. 일부 완료 결과·기한 종료를 정리하며 이미 나간 데이터의 회수나 앱 도착 시각을 보장하지 않는다. 59.5초 시작 시 남은 약 0.5초만 기다리는 경계와 기한 이후 새 전송 금지를 검증한다.
- [ ] 유효한 접속자가 없으면 수신자 없음으로 종료한다. 전송 성공·방 종료·만료·기한 초과도 구분하고, 알림 실패만으로 연결 중인 참여자를 퇴장시키지 않는다.
- [ ] 서버 재시작 시 미시작 대기와 최초 실패 시각·기한이 저장된 재시도 대기는 기존 규칙으로 복구하고 이미 기한이 지난 기록은 다시 발송하지 않는다. 최초 전송의 시작 기록만 있고 결과가 불명확한 기록은 D06 2번에 따라 재전송하지 않고 결과 불명 종료한다. 성공·실패·수신자 없음과 구분하며 업무 상태를 되돌리지 않는다. 재시작으로 새 60초를 부여하지 않는다.
- [ ] 관련 방 변경·조회·알림의 상태와 버전이 일치한다. 재전송은 원래 버전·내용을 유지하고 프론트가 현재보다 높은 버전만 적용하도록 문서화한다.
- [ ] D10 1번에 따라 참여·주문서 완료 등 적용 가능한 변경 요청의 성공 HTTP 응답에 명령 결과와 최종 저장 버전의 전체 공통 상태를 함께 반환한다. 최종 commit 이후 응답하고 공통 부분은 같은 버전의 발송 대기 snapshot과 일치한다. 같은 상위 트랜잭션의 중간 상태나 부분 응답의 숫자만으로 적용 버전을 올리지 않으며 전체 상태를 실제 적용했을 때만 올린다. 응답·알림의 도착 순서와 중복·역순에도 화면을 되돌리지 않고 명령 성공 결과는 별도로 처리함을 검증한다. 본인 퇴장·방 삭제·비참여자의 정보 범위를 확대하지 않으며 정확한 필드·응답 구조는 후속 계약에서 정한다.
- [ ] 각 상태 알림은 그 버전의 전체 공통 방 상태를 담아 더 최신 알림 하나로 상태를 교체할 수 있다. 같은 버전의 필수 상태를 여러 부분 알림으로 분할해 누락시키지 않으며 원래 snapshot을 재전송한다. 본인 외 답변·선호·투표 같은 비공개 정보를 포함하지 않는다.
- [ ] D11에 따라 접속 기록 변화도 같은 방 버전에 포함한다. 마지막 연결 끊김 감지·유예 내 복귀·재시작 시 유예 시작 등 실제 DB 값이 바뀌면 상태·버전·snapshot을 함께 저장하고 최종 commit 후 전송한다. 같은 값·heartbeat·다른 연결이 남은 상태의 단일 연결 종료만으로 새 버전을 만들지 않는다. 끊김 시각만 지워지는 복귀도 누락하지 않고 현재 60초 유예와 일반 참여자 퇴장·방장 종료를 유지한다. 접속 전이·재시작·같은 값·과거 접속 알림 무시를 검증하며 접속 기록을 실제 네트워크 상태의 즉각적 증명으로 취급하지 않는다.
- [ ] 최초 입장·재접속 조회는 현재 상태와 버전을 함께 반환하고 외부인의 방 조회 정보 범위와 기존 인증·계정 전환·유예 규칙을 보존한다.
- [ ] 사용자가 확인한 방 참여 중 닉네임 수정·사진 교체·초기화 금지 규칙을 서버에서도 검사한다. 실제 참여와 재접속 유예를 고려하고 방 참여와 프로필 저장의 동시 실행으로 우회되지 않도록 한다. 계정 전환용 검사 재사용만으로 미참여 PENDING 요청까지 제한 범위를 확대하지 않는다. 참여 중 프로필 변경의 실시간 방 전파 기능은 추가하지 않는다.
- [ ] D07 2번에 따라 발송 종료를 확정할 때 원문을 제거하고 처리 요약만 종료 시각부터 3일 보관한다. 성공 외 수신자 없음·방 종료·만료·기한 초과·D06 결과 불명 종료에도 적용한다. 없는 시각·결과를 추정하지 않으며 요약에 닉네임·사진·인증 비밀값·원문 예외를 복사하지 않는다.
- [ ] 3일이 지난 종료 요약만 주기 정리에서 나눠 삭제하고 진행 중 원문과 실제 방 상태는 보관 정리 대상으로 지우지 않는다. 종료 기록은 재전송하지 않으며 종료·원문 제거 저장 실패, 3일 전후 경계, 정리 중단·재실행을 검증한다.
- [ ] D09 2번에 따라 같은 API 프로세스 안의 별도 요약 정리 작업은 시작 후 첫 실행과 매 실행 완료 후 1시간 대기를 수행하며 중첩 실행하지 않는다. 한 묶음 최대 100건씩 저장을 확정하고 한 번 실행은 최대 10묶음·1,000건으로 제한한다. 실패한 묶음은 취소하고 앞서 확정한 묶음은 유지하며 다음 실행에서 남은 대상을 다시 찾는다. 초기 주기·한도와 각 경계·재시작을 검증하고 정확한 삭제 시각이나 처리량을 보장하지 않는다. 실제 검색 인덱스·실행 계획과 삭제 지연·누적 관측은 후속 계약으로 구체화한다.
- [ ] D08 1번에 따라 실제 방 연결은 nullable 외래 키와 ON DELETE SET NULL로 관리하고 변하지 않는 이력용 방 식별 정보를 별도로 보존한다. 없는 방으로의 연결 저장은 DB가 거절하며 방 물리 삭제 후 연결만 비워지고 종료 요약은 원래 종료 시각부터 3일 보관됨을 검증한다. 방 삭제로 요약을 연쇄 삭제하거나 종료 사유·시각을 초기화하지 않는다. FK가 방 활성 상태 검사·미완료 발송 종료·원문 제거를 대신한다고 취급하지 않는다.
- [ ] 필요한 스키마와 명시적 마이그레이션을 기존 데이터 보존·재실행·중단 후 재개 조건으로 제공한다. D08 방 삭제 참조 방향을 반영하고 구체 컬럼·잠금 순서·중간 중단 복구는 최종 실행 계약에서 구체화한다.
- [ ] 실제 REST·WebSocket과 제어 가능한 전송 실패·시각·재시작 경계로 저장 취소, 부분 실패, 전체 재전송, 중복·역순, 60초 기한과 접속자 없음 동작을 검증한다.
- [ ] 같은 기록의 즉시 발송·재시도가 겹칠 때 잠금과 DB 재확인으로 중복 실행을 조정하고, 다른 방 기록은 동시에 실행 가능함을 검증한다. 서버 재시작으로 메모리 잠금이 사라져도 DB 기록에서 미시작·저장된 실패 기한·미확인 최초 결과를 구분해 복구 또는 결과 불명 종료한다.
- [ ] 최초 시작 기록 저장 직후와 최초 전송 성공/실패 후 결과 저장 전의 중단에서 결과 불명 종료와 재전송 없음을 검증한다. 아직 미시작인 기록은 버리지 않으며, 이미 저장된 최초 실패 기한은 후속 재시도 결과 불명이나 재시작으로 초기화하지 않는다. 재접속 조회는 최신 상태·버전으로 화면을 복구할 수 있도록 계약·검증하고 프론트 브라우저 미검증을 구분한다.
- [ ] 실제 MySQL 독립 세션에서 버전·발송 대기 저장의 원자성·경합과 마이그레이션을 보완 검증한다. 환경이 없으면 해당 항목을 미검증으로 명시한다.
