# T01: 모든 퇴장 경로의 일관된 방 정리

## Parent

[개발 명세 #43](https://github.com/pknu-wap/WHATBOB_BE/issues/43), 원본 요청 #36.

## What to build

명시적 퇴장·연결 유예 만료·늦은 재접속·지연 및 주기 정리·계정 전환 전 정리 중 어느 경로로 참여자가 제거돼도 같은 인원과 완료 상태를 관찰할 수 있도록 정리 경계를 통합한다. 기존 인증·유예·종료 및 계정 전환의 원자성을 보존한다. 사용자 확정에 따라 일시적 DB 충돌 재시도와 주기 자동 퇴장의 방별 실패 격리를 포함한다.

각 진입 경로가 잠금 조회와 퇴장 대상 판단을 수행한 뒤 같은 방의 잠긴 대상 목록을 공통 정리에 전달한다. 공통 정리는 참여·완료 기록을 제거하고 최종 집계를 한 번 계산해 방 단위 결과를 반환한다. 전체 작업을 소유하는 상위 호출자가 commit·rollback을 담당한다. 기존 알림은 최종 저장 성공 이후 호출 경계에서 처리하고 필요한 기존 형식 변환도 그 경계에서 수행한다.

사용자가 두 티켓 분리를 선택했으므로 신규 DB 발송 대기·재시도·버전 규약과 그에 따른 알림 전파 확장은 후속 T01N에서 구현한다. 이 티켓은 정리 통합만으로 기존 동작을 검증할 수 있어야 한다.

## Acceptance criteria

- [ ] 명시적 일반 참여자 퇴장, 요청 중 지연 정리, 개별 유예 예약, 주기 정리, 늦은 재접속, 계정 전환 전 만료 정리가 동일한 실제 정리 경계를 사용한다.
- [ ] 참여자와 해당 완료 상태의 제거·인원 재계산이 같은 트랜잭션에 포함되고 중복 퇴장이 인원 중복 감소를 만들지 않는다.
- [ ] 공통 정리에 동일 참여 기록이 중복되면 한 번으로 합쳐 처리를 계속하고 중복 발견은 경고로 기록한다. 빈 목록은 삭제·불필요한 집계·퇴장 알림 없이 변경 없음으로 종료한다. 기존 명시적 퇴장의 없는 참여자 응답을 변경하지 않으며, D14 금지 대상의 전체 거절과 구분한다.
- [ ] 각 호출 경로가 최신 잠금 상태에서 대상을 판단하고 공통 정리에 같은 방의 잠긴 대상들을 전달한다. 기존 인증·계정 전환의 선행 잠금을 보존하며 방 영역은 Room → RoomMember → 완료 기록 순서를 따르고 복수 대상은 식별자 순서를 고정한다. 후보 탐색의 JOIN 정렬만으로 잠금 순서를 보장한다고 가정하지 않는다.
- [ ] 방 조회의 지연 삭제를 포함해 대상 판정·최종 집계는 최신 잠금 읽기와 적재 객체 갱신을 사용한다. 인증 선행 조회가 만든 MySQL 과거 스냅샷·ORM 캐시로 삭제 대상을 판단하거나 집계하지 않는다.
- [ ] 다른 방 참여자·방장 등 공통 일반 퇴장 정리의 계약 위반 대상이 하나라도 있으면 삭제 전에 전체 목록을 거절하고 상위 작업이 rollback한다. 올바른 대상도 부분 처리하지 않으며, 호출 계약 위반과 정상적인 중복·만료 경쟁을 구분한다.
- [ ] 공통 정리는 commit·rollback하지 않으며 계정 전환 같은 상위 작업 실패 시 정리도 함께 취소할 수 있다.
- [ ] MySQL 잠금 대기 만료(1205)·교착 상태(1213)에 한해 최상위 트랜잭션 전체를 rollback하고 최대 2회 즉시 추가 시도한다. 매번 권한·세션·최신 참여 및 유예 조건을 다시 확인한다. 공통 함수 내부·기존 계정 전환 재시도 안에 재시도를 중첩하지 않으며, 계약 위반·도메인 오류·결과 불명 커밋·일반 연결 장애는 이 재시도에 포함하지 않는다.
- [ ] 위 DB 충돌로 최대 3회 시도해도 실패한 방 HTTP 작업은 전체 rollback 후 HTTP 503과 `detail.code=ROOM_TEMPORARILY_UNAVAILABLE`, `detail.message=일시적으로 방 요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요.`를 반환한다. 프론트 자동 재전송을 요구하지 않으며 기존 인증·계정 전환 오류 코드와 내부 버그·도메인 오류를 이 응답으로 덮지 않는다.
- [ ] 복수 연결 중 마지막 연결 종료부터 기존 60초 유예가 적용되고 유예 내 재접속은 참여 상태를 보존한다.
- [ ] 방장 종료·방 만료·본인 퇴장 권한·사용자 및 인증 세션 재확인 규칙을 보존한다.
- [ ] 같은 방의 묶음 만료는 최종 남은 인원을 기준으로 한 번 집계하며 결과에 실제 퇴장자 목록과 최종 인원·완료 상태를 담는다.
- [ ] 주기적인 일반 참여자 자동 퇴장은 방마다 별도 트랜잭션으로 처리한다. 같은 방의 삭제·집계는 함께 확정·취소하되, 개별 방의 처리 실패로 다른 방의 성공을 되돌리지 않는다. 실패한 방의 제한적 재시도 후에도 실패하면 기록하고 다음 방으로 진행한다. 전역 장애와 취소 신호는 무조건 무시하지 않는다.
- [ ] 성공한 방의 결과는 나중 방 실패로 유실하지 않으며 기존 알림은 실제 저장이 확정된 방에만 보낸다. 공통 정리 함수는 계속 commit·rollback하지 않는다. 계정 전환·재시작 복구 등 별도 상위 문맥에 주기 실행의 실패 격리 정책을 무조건 적용하지 않는다.
- [ ] 기존 REST·WebSocket·정리 실행 경계를 통해 동작을 회귀 검증하고 방 조회는 올바른 인원·완료 상태를 반환한다. DB 변경 실패·상위 작업 취소도 검증한다.
- [ ] 기존 알림 처리에서 최종 저장 이전에 확정 퇴장 알림을 보내지 않으며, 새로운 전달 규약은 T01N과 구분한다.
- [ ] 신규 투표·다시 고르기·추가 제외 조건 정책과 새 알림 스키마를 이 구조 정리에 끼워 넣지 않는다.
