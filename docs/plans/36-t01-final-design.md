# #36 T01 최종 설계 확인안

- 상태: 2026-11-17 사용자 확인 완료. 최종안 확인 후 T01N으로 넘어갈지 묻는 질문에 사용자가 “다음”으로 답해, D01~D06·D14~D18과 아래 잠금·호출 경계·검증 구체화를 T01 설계로 확정했다. 실행 코드는 변경하지 않았다.
- 범위: 일반 참여자 퇴장의 공통 정리, 기존 제품 규칙 보존, 특정 DB 충돌 재시도, 주기 자동 퇴장의 방별 실패 격리. 알림 내구 저장·재전송·버전은 다음 T01N이다.
- 결정 근거: [아키텍처 질의응답 기록](36-t01-departure-architecture.md), [T01 티켓 초안](36-tickets/T01-member-departure-consistency.md).

## 1. 확정된 처리 흐름

1. 각 호출 경로가 인증·권한·유예·방 상태를 최신 잠금 조회에서 판단한다.
2. 같은 방의 잠긴 일반 참여자 목록을 공통 정리 함수에 전달한다.
3. 공통 함수는 전체 입력을 먼저 검증한다. 다른 방 참여자·방장 등 금지 대상이면 변경 전에 전체 거절한다.
4. 같은 참여 기록의 중복은 한 번으로 합치고 경고를 기록한다. 빈 목록은 변경 없이 종료한다.
5. 참여 기록과 주문서 완료 기록을 제거하고 최종 인원·완료 상태를 한 번 집계한다. 방 식별자·실제 퇴장자 목록·최종 집계가 담긴 내부 결과를 반환한다.
6. 상위 작업이 commit·rollback을 소유한다. 기존 알림은 실제 성공한 최종 commit 이후에만 보낸다. 공통 함수 안에는 commit·rollback·전송을 넣지 않는다.

같은 방의 삭제·집계는 함께 성공하거나 함께 취소한다. 중복 제거가 권한 오류나 DB 실패까지 무시한다는 뜻은 아니다. 기존 명시적 퇴장에서 없는 참여자에게 반환하는 응답은 유지한다.

## 2. 잠금·최신 읽기 계약

- 기존 계정 전환·인증의 사용자·세션·요청 작업 등 선행 잠금은 유지한다. 방을 먼저 잠그려고 인증 선행 순서를 뒤집지 않는다.
- 방 영역에서는 Room → 해당 RoomMember → 완료 기록 순서로 잠근다. 여러 방·참여자·완료 기록이 필요하면 각 단계에서 식별자 순서를 고정하고, JOIN의 정렬만으로 실제 잠금 순서가 보장된다고 가정하지 않는다.
- 퇴장 대상 판정과 최종 집계에 쓰는 방·참여·완료 상태는 최신 잠금 읽기로 얻는다. 이미 세션에 적재된 객체도 최신 값으로 갱신한다. MySQL REPEATABLE READ에서 앞선 인증 조회가 만든 과거 스냅샷이나 ORM 캐시를 집계의 근거로 쓰지 않는다.
- 같은 방의 참여 추가·완료 표시·연결 복구·연결 끊김 등 관련 변경도 필요한 범위에서 방 영역 순서를 맞춘다. 실제 삭제와 경쟁하는 인접 경로를 함께 확인하되 인증 정책을 재설계하지 않는다.
- 방 조회도 지연 정리를 통해 참여자를 제거하므로, 그 삭제 구간은 같은 잠금·최신 판정 계약을 따른다. 조회 응답의 기존 참여자 정보 공개 범위는 유지한다.
- 주기 정리의 후보 목록은 탐색용이다. 방별 트랜잭션에서 방 상태·참여 여부·최신 연결 끊김 시각을 다시 읽고 자동 퇴장 여부를 판정한다. 후보 탐색이 참여자를 잠근 채 여러 방 전체를 대기하게 만들지 않는다.

이는 이미 확정한 DB 잠금 방식의 구체화다. 같은 방 변경은 차례대로 실행되어 정합성을 지키지만 경합 시 대기가 생긴다. 관련 경로의 순서 정리·최신 읽기와 실제 MySQL 경합 검증이 구현 비용이며, 성능 개선을 실측한 상태는 아니다.

## 3. 경로별 트랜잭션·재시도 경계

| 경로 | 작업 소유 경계와 처리 |
| --- | --- |
| 직접 퇴장 | 기존 인증·본인 권한 재검증부터 삭제·집계까지 상위 HTTP 작업이 소유한다. |
| 요청 중 지연 정리 | 요청의 상위 트랜잭션 소유자가 확정한다. 방 조회의 정리 구간도 포함한다. 이미 확정된 상태를 실패한 전체 요청인 것처럼 되돌려 재실행하지 않는다. |
| 개별 연결 유예 예약·늦은 재접속 | 방과 참여자의 최신 상태에서 유예 만료를 재판정하고 상위 작업이 확정한다. 재접속이 이미 유예를 해제했으면 자동 퇴장시키지 않는다. |
| 주기 자동 퇴장 | 한 방씩 별도 트랜잭션으로 처리한다. 개별 방 실패는 기록하고 다음 방으로 진행하며 이전 성공을 유지한다. |
| 계정 전환 전 정리 | 전환 작업 전체에 소속한다. 공통 정리는 flush만 가능하고 기존 전환 재시도에 중첩하지 않는다. 후속 전환 실패 시 함께 취소한다. |
| 서버 재시작 복구 | 현재의 단계별 저장과 실패 전파 문맥을 보존한다. 주기 실행의 개별 방 실패 무시 정책을 자동 적용하지 않고, 기존 연결 끊김 시각·유예를 연장하지 않는다. |

- MySQL 1205·1213만 최상위 미확정 작업을 전체 rollback한 뒤 최대 2회 즉시 추가 시도한다. 잠금만 재획득하거나 삭제 함수만 반복하지 않고 권한·세션·방·참여·유예 조건을 다시 확인한다.
- 주기 실행은 실패한 방이 재시도 단위다. 기존 계정 전환은 전체 전환이 재시도 단위다. 공통 함수와 그 호출자를 각각 재시도하는 중첩 구조는 만들지 않는다.
- 결과 불명 commit·일반 연결 장애·도메인 오류·내부 계약 위반·이미 성공한 commit 뒤의 알림 실패는 이 재시도 대상이 아니다.
- 각 성공한 방의 결과를 이후 실패와 분리해 보존한다. 주기 실행의 전역 DB 장애와 취소 신호를 무조건 삼키지 않으며, 알림을 보내는 동안 DB 잠금을 유지하지 않는다.

## 4. 확정된 최종 실패 응답

DB 잠금 충돌로 최초 포함 세 번 모두 실패해 rollback이 완료된 방 HTTP 작업은 다음 응답을 반환한다.

```json
{
  "detail": {
    "code": "ROOM_TEMPORARILY_UNAVAILABLE",
    "message": "일시적으로 방 요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요."
  }
}
```

- HTTP 상태: 503.
- 새 프론트 자동 재전송을 요구하지 않는다. 기존 공통 오류 안내를 쓰거나 이 코드를 구분해 안내할 수 있다.
- 기존 인증·계정 전환의 오류 코드는 유지한다. 다른 내부 버그·도메인 오류를 이 일시 오류로 덮지 않는다.
- 백그라운드 작업은 HTTP 응답 대신 실패를 관측한다. 민감한 토큰·인증 비밀값을 로그에 넣지 않는다.

## 5. 기존 정책과 T01N 경계

- 기존 60초 재접속 유예·복수 연결·방장 종료·방 만료·계정 전환 제한을 유지한다. 자동 퇴장은 방 삭제와 구분한다.
- 서버 재시작 복구는 현재도 전체가 하나의 트랜잭션이 아니다. 이를 전체 원자 작업으로 바꾸거나 기동 실패 정책을 재설계하는 작업은 이 최종안에 포함하지 않는다.
- T01은 기존 알림 형식과 저장 이후 전송 원칙을 유지한다. T01N에서 누락 전파 경로·발송 대기·재시도·방 상태 버전을 통합한다. T01이 알림 수신 보장을 제공한다고 표시하지 않는다.
- T01에는 새 테이블·컬럼 변경을 계획하지 않는다. 구현 중 스키마 필요성이 발견되면 근거와 범위를 다시 제시한다.
- 제품 보류 Q19(다시 고르기)·Q20(추가 제외 조건)은 미정으로 유지한다. 새 라운드 기능은 T02 이후 범위다.

## 6. 검증 계획과 완료 기준

검증의 기본은 사용자가 확인한 인증 REST·방 WebSocket의 외부 동작이며, 실제 정리 실행 경계와 격리 MySQL 경합 검증을 보완한다.

- 여섯 제거 경로가 같은 실제 정리를 사용하고 참여·완료 기록 제거 후 최종 인원·완료 상태가 일치하는지 확인한다.
- 같은 방 복수 퇴장·빈 대상·중복 대상·다른 방 및 방장 입력 거절·상위 rollback·없는 참여자의 기존 응답을 확인한다. 외부에서 만들 수 없는 내부 입력 계약은 그 경계의 집중 테스트로 보완한다.
- 1205·1213의 첫 실패 후 성공과 세 번 소진을 제어해 시도 횟수·최신 조건 재판정·전체 rollback·503 오류 계약을 검증한다. 계약 위반·일반 장애를 무분별하게 재시도하지 않는지도 확인한다.
- A방 성공·B방 실패·C방 성공 시 A/C 저장과 결과가 유지되고 B만 취소되는지, 실패한 작업에서 확정 퇴장 알림을 보내지 않는지 확인한다.
- 독립 MySQL 세션으로 직접 퇴장 대 자동 퇴장, 유예 만료 대 재접속, 정리 대 참여·완료 표시를 경합시킨다. 인증의 일반 조회·ORM 선적재가 먼저 있어도 최신 잠금 읽기로 집계하는 경우를 포함한다.
- 기존 호스트 종료·방 만료·계정 전환 실패·재시작 유예와 참여자 정보 공개 범위를 회귀 확인한다.
- MySQL은 `MYSQL_TEST_DATABASE_URL`로 지정한 격리 테스트 환경을 사용한다. 기존 테스트의 DB 검증·격리 패턴을 재사용하며 운영 DB에서 실행하지 않는다. SQLite만으로 행 잠금 검증 완료를 주장하지 않는다.
- 테스트 환경이나 의존성이 없으면 미검증 항목과 이유를 기록한다. 실제 실행하지 않은 테스트를 통과로 기록하지 않는다.
