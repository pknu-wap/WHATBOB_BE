# #50 왓밥 로그아웃 후 카카오 계정 선택

2026-11-18 사용자 흐름 및 설계 기준 확정. [GitHub 이슈 #50](https://github.com/pknu-wap/WHATBOB_BE/issues/50)의 제목은 `[feat] KAKAO Refresh Token/ Logout`이며 조회 시 본문과 댓글은 비어 있었다.

이 문서는 웹을 가정했던 초기 설계의 기록이다. 후속 합의에서 웹과 iOS·Android용 Expo 앱을 모두 구현 대상으로 정하고 카카오 토큰 갱신과 폐기를 추가했다. 현재 구현 범위와 검증 기준은 [#50 통합 명세](../specs/50-kakao-token-lifecycle-and-logout.md)를 따른다.

## 합의한 목표

왓밥에서 로그아웃한 뒤 다시 카카오 계정을 연결하는 사용자는 이전에 사용한 계정이나 다른 계정을 직접 선택할 수 있다.

## 사용자 흐름

1. 왓밥 로그아웃을 확정하면 새 UUID 사용자로 돌아온다. 카카오 계정 선택은 이 UUID 세션에서 사용자가 다시 연결을 시작할 때 제공한다. 연결이 완료될 때까지 새로고침, 취소, 인증 실패 후에도 다시 선택할 수 있다.
2. 일반 브라우저에서는 카카오를 통해 같은 계정 또는 다른 계정으로 인증한다. 카카오톡 내장 브라우저에서 계정 선택이 불가능하면 연결을 중단하고 일반 브라우저를 안내한다. 내장 브라우저의 UUID 기록은 해당 브라우저에 남으며, 일반 브라우저에서 연결할 때는 그 브라우저의 UUID 기록이 대상이 된다.
3. 카카오 인증을 마치면 왓밥에서 연결 대상의 카카오 닉네임과 제공 받은 이메일의 마스킹된 값을 보여준다. 사용자가 확인할 때만 이관을 확정한다. 두 정보가 모두 없으면 연결을 중단하고 현재 UUID로 돌아갈 수 있게 한다.
4. 이전 카카오 계정을 선택하면 새 UUID로 쌓은 기록이 해당 계정에 합쳐진다. 다른 계정을 선택하면 새 UUID 기록은 선택한 계정에 이관되고, 로그아웃 전에 이전 카카오 계정에 있던 기록은 그 계정에 남는다. 확인 화면에서 취소하면 현재 UUID와 기록으로 돌아간다.

## 현재 인증과 로그아웃

- 왓밥의 `LOGOUT` 계정 전환을 확정하면 현재 브라우저의 왓밥 세션이 종료되고 새 UUID 사용자와 세션이 발급된다. 다른 기기의 왓밥 세션과 기존 카카오 계정의 기록은 보존된다. 방 참여 또는 재접속 유예 중에는 전환이 제한된다. [UUID 인증 API](../UUID_AUTH_API.md#logout-왕복-규칙-t08), [방 재접속과 계정 전환 ADR](../adr/0002-room-reconnect-and-account-switching.md)
- `POST /api/auth/tokens`는 유효한 왓밥 세션 쿠키로 왓밥 JWT를 재발급한다. 카카오 액세스 토큰은 로그인·계정 연결 시 사용자 정보 조회에 사용한다. [JWT 복원 계약](../UUID_AUTH_API.md#최초-이용과-재방문), [카카오 연동 코드](../../app/auth/kakao.py)
- 확인한 프런트엔드 `main`은 `/api/auth/kakao/login/url`에서 인가 URL을 받고 콜백에서 `state`를 검증한 뒤 기존 단독 로그인 `/api/auth/kakao/login`을 호출한다. #50은 프런트엔드가 UUID 인증과 `KAKAO_LINK`·`LOGOUT` 계정 전환을 사용하는 흐름을 전제로 한다. 실제 배포본의 동작은 브라우저에서 별도로 확인한다. [프런트엔드 인증 소스](https://github.com/pknu-wap/WHATBOB_FE/blob/21c3436b172e6c2d14449fc2b914e81f140cb548/app/src/lib/auth.ts), [프런트엔드 콜백 처리](https://github.com/pknu-wap/WHATBOB_FE/blob/21c3436b172e6c2d14449fc2b914e81f140cb548/app/src/lib/web-auth.ts)

## 연동 설계 제안

- 로그아웃 확정과 같은 트랜잭션에서 새 왓밥 세션에 재연결 표시를 기록한다. 프런트엔드는 세션 복원 응답에서 이를 확인한다. 연결 확정으로 이 UUID 세션이 종료될 때까지 표시가 유효하다. 로그아웃 확정 응답이 유실된 경우에도 같은 세션을 복구한다.
- 일반 브라우저의 재연결 인가 요청에는 카카오 재인증을 요청하는 `prompt=login`을 사용한다. 카카오 공식 문서에 따르면 `prompt=select_account`는 저장된 간편로그인 정보에 따라 자동 로그인되기도 한다. 카카오톡 내장 브라우저에는 `prompt=login`이 제공되지 않으므로, 재연결에서 계정 선택을 보장할 수 없을 때 인가 요청 전에 안내한다. [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api), [카카오계정 간편로그인](https://developers.kakao.com/docs/ko/kakaologin/utilize)
- 카카오 콜백의 `state`를 검증한 후 기존 `KAKAO_LINK` 준비 단계를 호출한다. 준비 응답은 해당 카카오 계정의 닉네임과 서버에서 마스킹한 이메일을 보여주는 데 필요한 범위로 확장한다. 사용자의 확인으로 기존 확정 단계를 호출하며, 서버는 준비 때 인증된 계정과 현재 UUID 세션을 기준으로 이관한다. 취소·만료 후 늦게 도착한 확정 요청과 여러 탭에서 대상이 바뀐 요청을 거절할 수 있도록 준비 내역 및 확인의 결합을 설계한다.

## 검증할 사용자 시나리오

- 일반 브라우저에 카카오 로그인 정보가 남은 상태에서 기존 계정 재선택과 다른 계정 선택을 각각 확인한다. 첫 연결, 새로고침, 취소 후 재시도도 확인한다.
- 확인 취소, 표시 정보 누락, 준비 만료, 탭 간 대상 변경, 연결 확정 응답 유실 시 기록 이관과 세션 복구 결과를 확인한다.
- 방 참여·재접속 유예 중에는 계정 전환이 차단되는지 확인한다. 같은 계정·다른 계정으로 연결한 경우 UUID 활동의 이관 대상과 다른 기기의 세션을 각각 확인한다.
- 카카오톡 내장 브라우저의 안내와 일반 브라우저에서 별도 UUID로 이용을 이어가는 흐름을 실제 기기에서 확인한다.
