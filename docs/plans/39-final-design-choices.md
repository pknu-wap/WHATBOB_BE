# #39 남은 제품·자원 선택 4묶음

2026-11-13. 사용자가 **M1A·M2A·M3A·M4A를 모두 선택했다.** T02 주요 10항목과 R1A·R2A·R3A·R4A·R5A도 선택 완료다. 아래 B안은 비교 이력이며 채택하지 않았다. 선택은 설계 정책의 확정이고 코드·모델·운영 설정 적용이나 테스트 통과를 뜻하지 않는다. 상세 계약은 [통합 아키텍처](39-implementation-architecture.md), 실제 검증 계획은 [T09](39-validation-and-handoff.md)를 따른다.

## M1. 개인 선호의 첫 반영 강도와 최근성

오늘 답변 점수를 100점으로 환산해 설명한다. 실제 추천 응답의 기존 점수 단위를 바꾸는 결정은 아니다. 두 방식 모두 공용 로지스틱 모델·명시적 만족 라벨·누적 유효 평가·최근 평가 우선 정책을 유지한다.

- [x] **M1A — 약하게 시작하고 취향은 천천히 바꾸기(추천).** 모델 개인 보정은 최대 ±5점, 최근성 반감기 90일, 증거 완화 기준 k=5를 초기 설정으로 제안한다. 근접 후보 안에서는 개인화 추첨 가중치의 최대 비율을 1.5:1로 제한한다. 같은 성격의 평가가 90일 전이면 최근 평가의 절반 무게를 가진다. 평가 이력은 삭제하지 않는다. 적은 평가의 보정은 더 작다. 장점: 오늘 답변과 일시적 기분에 덜 흔들린다. 비용: 바뀐 취향이 강하게 반영되기까지 늦을 수 있다.
- [ ] **M1B — 조금 더 강하고 빠르게 반영하기.** 최대 ±10점, 반감기 30일, k=5, 근접 후보 추첨 가중치 최대 2:1. 장점: 최근 취향 변화에 더 빨리 반응한다. 비용: 단기간 평가가 순위에 더 큰 영향을 줄 수 있다. 한 후보 +10/다른 후보 -10이면 두 후보의 개인 보정 차이는 최대 20점이다.

제안 수식은 `c=alpha*(n_eff/(n_eff+k))*(2*p-1)`이다. n_eff는 후보 메뉴/분류에 관련된 사용자 유효 평가의 시간 가중 증거량이며 관련 집계 정의는 특징 버전에 고정한다. 최근성은 유효 평가의 서버 확정 시각 기준으로 적용하고 원본 건수/이력도 함께 보존한다. k=5는 평가 5개가 무조건 충분하다는 보장이 아니라 증거량이 적을 때 완화하는 계수다. 어느 수치도 빅테크 공통 정답이 아니다.

두 안 모두 **기존 메뉴별 최신 불만족 0.35 감점을 새 누적 보정으로 교체**하는 초안을 포함한다. 기존 최근 추천 감점·종류 다양성·추첨은 유지한다. 모델이 없거나 검증을 통과하지 못하면 개인 보정 없이 오늘 답변과 기존 다양성/최근 노출 기준으로 추천하고, 누적 이력은 계속 저장한다. 이때 개인화 모델이 이미 작동한다고 표시하지 않는다. M1A 선택으로 이전 0.35를 중복 적용하지 않는 방향이 확정됐다. 모델 없이도 누적 선호 점수 적용을 원하면 이 묶음에서 별도 논의한다.

기존 알고리즘은 10% 근접 점수 안의 종류를 균등 추첨하므로, 작은 모델 보정만 더하면 모든 후보가 같은 추첨 대상에 남아 선택 확률이 변하지 않을 수 있다. 이를 막기 위해 **종류별 중복 방지·근접 점수 범위·최근 노출 감점은 유지하고, 근접 후보의 균등 추첨을 제한된 개인화 가중 추첨으로 바꾸는 제안**을 두 안에 포함한다. 가중치 `w=1+beta*r*p`에서 A는 beta=0.5, B는 beta=1.0이다. 모델/개인 이력이 없으면 w=1로 기존 균등 추첨이다. 종류별 가중치를 메뉴 개수만큼 더하지 않아 상품 수가 많은 종류가 유리해지지 않게 한다. 이 변경도 사용자의 M1A 선택에 포함된다. 최종 두 후보의 전체 선택 확률 비율은 후보 자격·반복 노출·그룹 구성에도 영향을 받으므로 위 상한은 개인화 추첨 가중치 자체의 상한이다.

## M2. 첫 섭취 불가 재료 목록의 범위

알레르기 선택 catalog와 별개다. 메뉴 원재료 전체가 없는 현 데이터에 새 코드만 붙여 정확성이 생기는 것은 아니다. 두 방식 모두 기존 제외 효과를 유지하고 정확 대응·매핑 검증이 필요하다.

- [x] **M2A — 8개 넓은 재료군으로 시작(추천).** 돼지고기·소고기·가금류·해산물·달걀·유제품·밀·대두/콩. 장점: 선택이 빠르고 초기 입력/매핑 범위를 제한한다. 비용: 해산물을 선택하면 생선·갑각류·오징어·조개류까지 넓게 제외하는 등 후보가 많이 줄 수 있다. 가금류와 해산물의 포함 범위는 catalog 설명에 명시한다.
- [ ] **M2B — 더 세분화한 목록부터 설계.** 예를 들어 생선은 먹지만 새우는 못 먹는 경우를 따로 고르게 한다. 장점: 필요 이상으로 제외하는 일을 줄일 수 있다. 비용: 정확한 세부 목록·메뉴 매핑 검토가 더 필요하므로 이 안을 고르면 목록을 한 번 더 검토한다.

M2A의 코드 초안은 `pork,beef,poultry,seafood,egg,dairy,wheat,soybean`이다. ALLERGY `milk`와 UNABLE `dairy`처럼 뜻이 다른 코드를 무조건 같은 것으로 취급하지 않는다. 각 코드의 확인된 메뉴 매핑과 미확인 건수를 검증 자료로 제공한다. 실제 검증 없이 완전한 재료 제외나 알레르기 안전성을 보장하지 않는다.

## M3. 주기적 모델 학습을 어디에서 실행할까

실제 서비스의 예측은 이미 선택한 대로 기존 API 프로세스에서 한다. 여기서는 모델을 만드는 학습 작업의 위치만 고른다.

- [x] **M3A — 현재 개발 PC 등 별도 기존 환경에서 학습(추천).** 원시 식별자·인증정보를 뺀 학습용 자료로 주기적으로 모델을 만들고, 검증된 작은 artifact만 서버에 반영한다. 초기 운영 주기는 주 1회 점검/수동 실행을 제안한다. 장점: 1GB의 MySQL·API와 학습 메모리를 경쟁시키지 않는다. 비용: 학습 자료 전달·실행·검증·반영 절차를 관리해야 한다. 사용자의 PC 가용성·허용된 자료 경로를 실제 구현 때 확인한다. 새 유료 서버를 자동 생성하지 않는다.
- [ ] **M3B — 같은 1GB 서버에서 한가할 때 학습.** 장점: 별도 환경으로 학습 자료를 옮기는 일이 줄어든다. 비용: 비혼잡 시간이라도 순간 메모리 부족으로 API·DB에 영향을 줄 수 있다. 별도 프로세스 1개·학습 크기/메모리/CPU 제한·자원 사전 측정을 통과한 경우에만 실행한다. 측정 실패면 학습을 보류하고 기본 추천을 유지한다.

어느 쪽도 운영 데이터 내보내기·스케줄러 설치·모델 활성화가 이미 수행됐다는 뜻은 아니다. 사용자 식별자를 제거한 특징도 취향 정보를 담으므로 공개 파일·외부 서비스에 업로드하지 않는다. 실제 작업은 내일 구현/검증 범위와 접근 권한 안에서 진행한다.

## M4. 5MB 사진의 압축 해제 크기도 제한할까

파일은 5MB 이하여도 픽셀 수가 매우 크면 메모리를 많이 쓸 수 있다. 1,200만 픽셀의 RGBA 배열 하나만 단순 계산으로 약 48MB이며 디코딩·변환·원본 버퍼는 별도다. 이 숫자는 서버 실측치가 아니다. [Pillow 공식 설명](https://pillow.readthedocs.io/en/stable/reference/Image.html)은 픽셀 수 기반 제한을 제공한다.

- [x] **M4A — 픽셀 상한과 프로필용 크기로 정규화(추천).** 5MB 이하이면서 최대 1,200만 픽셀인 JPG/PNG/WebP를 받고, 긴 변 최대 512px·비율 유지로 저장하는 초기안을 제안한다. 정지 이미지 한 장으로 정규화하고 위치 등 부가 메타데이터를 제거한다. 초과/애니메이션은 명확한 오류로 거절하고 이전 사진을 유지한다. 장점: 메모리·저장·전송량을 관리하기 쉽다. 비용: 5MB 이하여도 고해상도 사진은 줄여서 다시 올려야 하고 원본·애니메이션을 그대로 보존하지 않는다.
- [ ] **M4B — 수용할 해상도/애니메이션 범위를 더 검토.** 장점: 큰 휴대폰 사진이나 WebP 애니메이션의 원하는 동작을 먼저 정할 수 있다. 비용: 별도 처리 자원·프론트 축소·파일 처리 정책을 추가 검토해야 하며 1GB 서버에서 제한 없이 처리한다고 승인하지 않는다.

사용자가 M4A를 선택해 5MB·1,200만 픽셀 상한, 긴 변 최대 512px·비율 유지, 정지 이미지 저장·부가 메타데이터 제거를 설계 기준으로 확정했다. 실제 적용은 내일 구현한다. R5A의 공개 URL 정책은 유지한다.

최종 선택: `M1A, M2A, M3A, M4A`. M1의 기존 불만족 감점 교체·제한 가중 추첨과 모델 불가 시 개인 보정 없는 대체 경로도 포함한다. M2는 8개 재료군, M3는 별도 기존 환경의 주 1회 점검/수동 학습, M4는 위 정규화 기준이다. 실제 데이터 매핑·모델 성능·1GB 부하는 내일 검증할 대상이며 설계 문서만으로 통과 처리하지 않는다.
