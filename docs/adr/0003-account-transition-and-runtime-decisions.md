# 단일 API 프로세스와 계정 전환·사진 조회 정책

2026-11-13 사용자가 공통 설계 R1A·R2A·R3A·R4A·R5A를 선택했다. RAM 1GB에서 백엔드와 MySQL을 함께 실행하므로 API 프로세스 하나를 기준으로 하고, 방의 지속 상태는 DB에 보존한다. 다중 API 프로세스·메시지 시스템의 비용을 지금 부담하지 않는 대신 재시작 시 연결 복구와 용량 검증이 필요하다.

카카오 연결·로그아웃은 준비 비밀값 수신 후 확정하는 두 단계로 설계한다. UUID 기록을 카카오 계정으로 옮길 때 원본 사용자 행은 관련 기록·참조·인증 정리와 같은 트랜잭션에서 물리 삭제한다. 비활성 원본 행을 남기는 대안은 채택하지 않았으므로, 성공 작업의 복구 근거는 원본 행 없이도 유지돼야 한다. 이는 [ADR-0001](0001-uuid-users-with-optional-kakao-linking.md)의 UUID 폐기를 구체화한다.

현재 웹의 다른 탭에는 계정 변경 힌트를 보내고 서버 인증을 재확인한다. 알림 자체로 인증하거나 이전 사용자 요청을 새 사용자로 자동 재실행하지 않는다. [ADR-0002](0002-room-reconnect-and-account-switching.md)의 방 이용·60초 유예·참여 결과 불명 중 전환 금지는 유지한다.

업로드 사진은 주소를 알면 조회 가능한 URL로 제공한다. 사진 조회의 JWT·방 권한 검사·서명 만료는 채택하지 않고 업로드·교체·삭제의 본인 인증은 유지한다. UI는 본인 프로필·방 참여자 표시만 제공하며 클릭·확대·공유 기능은 만들지 않는다. 이 결정은 URL 비노출·외부 접근 차단을 보장하지 않는다.

정책 선택의 기록이며 실행 코드·운영 설정·DB 변경이나 성능 검증 완료를 뜻하지 않는다. 세부 초안은 [통합 구현 아키텍처](../plans/39-implementation-architecture.md)를 따른다.

후속으로 사용자는 M1A·M2A·M3A·M4A를 선택했다. 1GB 서비스 서버의 자원을 보호하기 위해 학습은 별도 기존 환경에서 하고, 사진은 5MB·1,200만 픽셀 이하 입력을 긴 변 512px의 정지 이미지로 정규화한다. 추천은 누적 유효 평가를 입력으로 쓰되 최대 ±5점(100점 환산)·90일 반감기로 약하게 시작하고, 근접 후보의 개인화 추첨 가중치도 제한한다. 세부 수식·초기 목록·가중치와 실제 검증은 [선택 기록](../plans/39-final-design-choices.md)을 따른다.
