# #39 UUID 기본 이용과 선택적 카카오 로그인 설계

상태: 구현 명세 작성·게시 완료, 기능 미구현. 2026-11-07까지의 대화에서 합의한 동작과 구현 시 적용할 기술 기준을 정리했다. 실행 코드·API·DB에는 아직 반영하지 않았다.

구현 명세: [로컬 명세](specs/39-uuid-users-and-kakao-migration.md), [GitHub #39](https://github.com/pknu-wap/WHATBOB_BE/issues/39). 이슈 상태는 `ready-for-agent`다.

관련 문서: [용어집](../GLOSSARY.md), [사용자와 계정 이관 ADR](adr/0001-uuid-users-with-optional-kakao-linking.md), [방 재접속과 계정 전환 ADR](adr/0002-room-reconnect-and-account-switching.md).

## 기본 이용

- 첫 방문 시 별도 가입이나 버튼 조작 없이 UUID 사용자, 중복 없는 랜덤 닉네임, 기본 프로필 이미지를 자동 제공한다.
- 랜덤 닉네임은 단어 조합과 숫자로 생성한다. 기존 닉네임과 중복되면 다시 생성한다.
- 같은 브라우저의 재방문에서는 같은 사용자와 닉네임·기록을 유지한다. 별도 기기 또는 브라우저 데이터 삭제 후에는 새 UUID로 시작한다.
- 개인 추천, 알레르기·섭취 불가·비선호 설정, 식사 기록과 같이 고르기 참여는 동일한 UUID 사용자에게 연결한다.
- 카카오 로그인 없이 개인 기능과 같이 고르기를 사용할 수 있다. 카카오 로그인은 기록을 계정으로 옮겨 이어 쓰려는 사용자를 위한 선택 기능이다.

## 카카오 로그인과 기록 이관

- 현재 UUID 사용자로 이용하다 카카오 로그인에 성공하면 해당 기록을 카카오 계정으로 이관하고 UUID를 폐기한다.
- 같은 카카오 계정으로 로그인한 다른 UUID의 기록도 그 계정으로 합친다. 어느 한 UUID 사용자를 대표 사용자로 남기지 않는다.
- 다른 브라우저의 UUID 기록은 해당 브라우저에서도 동일한 카카오 계정으로 로그인한 뒤에 이관한다.
- UUID 도입 이전부터 있던 카카오 계정에 로그인하면 기존 계정의 프로필과 기록을 보존하고 UUID 기록을 그 계정에 합친다.
- 새 방식으로 연결된 계정의 기본 프로필은 이관 대상 중 가장 먼저 생성된 UUID의 닉네임·사진을 기준으로 한다. UUID 생성 순서와 카카오 로그인 순서는 구분한다.
- 카카오 계정에서 직접 수정한 프로필은 더 오래된 UUID 기록을 나중에 이관하더라도 유지한다. 카카오에서 조회한 닉네임·사진으로 자동 덮어쓰지 않는다.
- 알레르기·섭취 불가·비선호 목록은 모두 합치고 같은 유형의 같은 항목만 중복 제거한다. 기존 요청의 목록 길이 제한 때문에 병합 데이터를 임의로 버리지 않는다.
- 식사 기록, 추천 이력과 피드백은 모두 보존한다. 반복 로그인 때문에 같은 원본 기록이 두 번 이관되지 않도록 한다.
- 로그아웃하면 새 UUID와 랜덤 닉네임으로 시작한다. 카카오 계정의 기존 기록은 보존하고, 다시 로그인할 때 새 UUID 기록도 이관한다.

## 방 참여와 계정 전환

- 방장과 일반 참여자 모두 방 참여 중에는 로그인·로그아웃할 수 없다.
- 로그인 대상 카카오 계정이 다른 기기에서 방에 참여 중이어도 로그인을 제한한다.
- 마지막 방 연결이 끊겨도 60초 동안 기존 참여 상태를 유지한다. 유예 중에는 계정 전환 제한도 유지한다.
- 60초 안에 재접속하면 기존 방 참여 상태로 복귀한다.
- 일반 참여자가 60초 안에 돌아오지 않으면 자동 퇴장한다. 방장이 돌아오지 않으면 방을 종료한다.
- 기존 일반 참여자를 오프라인 상태로 계속 남겨두는 동작은 새 자동 퇴장 규칙으로 대체한다.

## 프로필 편집

- UUID 이용 중과 카카오 로그인 후 모두 닉네임과 프로필 사진을 수정할 수 있다.
- 닉네임은 앞뒤 공백을 제거한 뒤 2~20자로 제한한다. 한글·영문·숫자·공백을 허용한다.
- 다른 사용자가 사용 중인 닉네임은 거절한다. 본인의 기존 닉네임을 그대로 저장하는 것은 중복 사용으로 보지 않는다.
- 기본 프로필 이미지를 제공하고 본인 사진 업로드·교체·삭제를 지원한다.
- 업로드 형식은 JPG·PNG·WebP, 최대 용량은 5MB다. 사진을 삭제하면 기본 이미지로 돌아간다.

## 사진 저장 범위

- 이번 개발에서는 로컬 파일 저장을 사용한다.
- 업로드 파일은 설정 가능한 데이터 디렉터리에 저장하고 Git 관리 대상에서 제외한다.
- 운영용 파일 저장소는 운영 준비 때 추가한다. S3 또는 다른 외부 저장소는 아직 선택하지 않았다.
- 운영 저장소 생성, 외부 서비스 연결 및 배포 작업은 이번 범위에 포함하지 않는다.

## 구현 시 적용할 기술 기준

아래는 기존 코드와 합의한 동작을 연결하기 위한 구현 기준이며, 현재 구현 완료를 뜻하지 않는다.

- 기존 내부 정수 사용자 PK와 관련 외래키는 가능한 한 유지하고 UUID 사용자 식별·카카오 계정 연결 상태를 별도로 관리한다.
- UUID는 사용자 식별자로 사용하고, 본인 요청은 별도의 비밀 인증 정보로 확인한다. 현재 Bearer 인증과 WebSocket 인증 흐름을 활용한다.
- 재방문 인증은 브라우저에 보관된 인증 정보로 자동 복원한다. 접근 토큰 만료만으로 UUID 사용자의 기록을 잃지 않도록 갱신·복원 계약을 제공한다.
- 이관 완료 시 원래 UUID의 인증 정보는 폐기하고 현재 브라우저는 카카오 계정의 인증 상태로 전환한다.
- 카카오 인증 실패, 방 참여 제한 또는 이관 오류 시 UUID와 원본 기록을 보존한다. 기록 이관과 UUID 폐기는 일관된 트랜잭션으로 처리한다.
- 기존 기록의 ID·일시와 피드백 순서를 유지한다. 이미 이관된 기록을 재생성하거나 이름만으로 식사 기록을 삭제하지 않는다.
- 닉네임 중복 및 같은 카카오 계정으로의 동시 이관은 DB 제약과 트랜잭션으로 제어한다.
- 업로드는 확장자뿐 아니라 실제 이미지 형식과 용량을 검증하고 서버가 생성한 파일명으로 저장한다.
- 방 접속 유예는 여러 탭의 마지막 연결, 재접속과 정리 작업의 경합 및 서버 재시작 후 복구를 고려한다.
- 기존 DB 변경은 마이그레이션 스크립트로 제공한다. 현재 프로필 API 문서는 구현 변경 때 실제 계약에 맞춰 갱신한다.

## 검증할 동작

- 최초 UUID 생성, 같은 브라우저 재방문 복원, 다른 브라우저의 독립 사용자 생성.
- 개인 기능과 방 참여의 동일 사용자 연결 및 타 사용자 기록 접근 차단.
- 랜덤 닉네임 충돌, 닉네임 길이·문자·중복 검증 및 직접 편집.
- 기본 사진, 유효한 업로드·교체·삭제 및 잘못된 형식·초과 용량 거절.
- 단일·다중 UUID 기록 이관, 기존 카카오 계정 보존, 프로필 우선순위 및 직접 수정값 유지.
- 제외 목록 전체 병합, 식사·추천·피드백 기록 보존, 재시도·동시 로그인·실패 시 원본 보존.
- 방 참여 중 로그인·로그아웃 제한과 다른 기기의 대상 계정 참여 확인.
- 60초 안 재접속, 유예 만료 후 참여자 자동 퇴장·방장 종료 및 완료 인원 재계산.
- 로그아웃 후 새 UUID 생성과 기존 카카오 기록 보존.

## 최종 확인

사용자가 합의한 내용을 명세로 작성하도록 요청했고, REST API·WebSocket 통합 테스트와 전용 MySQL 동시성 검증 경계도 확인했다. 구현은 게시한 명세를 기준으로 진행하며, 실제 API 요청·응답과 프론트 연동 계약은 구현 단계에서 문서·테스트와 함께 검증한다. 명세 게시가 기능 구현 완료를 뜻하지는 않는다.
